# PitGuard V3.87.14 云端加载流式化与分阶段工作区稳定性

## 1. 诊断结论

本次诊断包显示，后台计算和配筋任务均正常完成，页面长时间停留在 92% 发生在任务完成后的工程数据回读阶段：

- 一键闭合任务耗时约 140.4 s，正常成功；
- 配筋任务耗时约 42.6 s，正常成功；
- 配筋完成后完整工程数据约 13.44 MB；
- 普通 workspace 投影仍约 9.30 MB；
- 页面同时读取工程 workspace、核心状态、配筋方案/深化数据，旧进度条仅用时间估算并固定停在 92% 左右；
- 生产 Nginx 对 API 关闭缓冲且未统一压缩，多路大 JSON 在远程链路上相互竞争。

因此该现象不属于 Worker 死锁，主要由“任务完成后的多路大对象并行回读 + 伪进度 + 页面级遮罩”造成。

## 2. 修复内容

### 2.1 工程 shell 投影

项目打开默认使用 `profile=shell`。该投影保留工程几何、当前计算摘要和流程状态，但从首屏响应中移除数千条配筋检查与构造检查。权威 workspace 数据不变，完整列表由专用接口按需读取。

### 2.2 配筋数据分级读取

`GET /api/projects/{project_id}/rebar/design-scheme` 新增：

- `detail=summary`：首屏返回全部构件方案和优先问题，但仅返回有限条复核记录；
- `detail=full`：显式读取完整方案；
- `GET .../design-scheme/checks`：分页读取完整复核记录。

配筋页面先显示主方案，再静默读取图纸目录和深化数据。点击“加载完整复核列表”时才传输全部检查记录。

### 2.3 分阶段 core-status

核心状态接口支持 `detail=summary|stage|full` 和当前阶段参数。普通页面只计算当前阶段需要的稳定性、验证、配筋或交付数据，避免每次刷新都重建全部证据域。

### 2.4 真实传输进度

浏览器改为流式读取响应体，显示：

- 正在连接服务器；
- 服务器已响应；
- 已接收字节数；
- 正在解析数据；
- 数据已就绪。

连续一段时间没有字节进展时会中止本次读取，并保持页面其他功能可用。

### 2.5 非阻断读取界面

GET 读取任务不再模糊或锁定整个页面，改为右上角紧凑状态卡。写入、计算和方案采用仍使用阻断式进度。

### 2.6 云端传输与代理

- FastAPI 对 JSON 启用 GZip；
- 生产 Nginx 启用 gzip；
- 普通 API 响应恢复代理缓冲；
- 大型不可变成果仍通过独立下载路径处理；
- 增加慢请求诊断流 `diagnostics/http-performance.jsonl`。

## 3. 兼容性

结构算法版本保持 V3.87.10。V3.87.14 只调整数据投影、网络传输、工作区装载和诊断，不会因为升级本身使已有有效结构计算失效。
