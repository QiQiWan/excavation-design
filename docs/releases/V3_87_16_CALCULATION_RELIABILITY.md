# V3.87.16 计算可信性修复交付说明

日期：2026-10-25。基线：上传的 V3.87.15 源码；隔离审查基线提交 `76295ab`。

## 1. 本轮结论与范围

本轮已将用户指定的六项工作落实到计算内核、任务/API、结果合同和主界面，并建立可重复的反例回归。重点是让软件如实给出“给定方案算了什么、哪些结果可用、哪些尚不成立”，并保证最终需求使用本次最终求解结果。

交付类型为源码修复包，工程成熟度仍属于受限分析与审查。程序测试通过不等于岩土方法验证通过，也不等于原项目计算书、施工图已经成为可发行成果。原上传参考计算书和图纸用于上一轮缺陷分析，本轮没有宣称已完成其整套工程模型的同条件复现或第三方软件标定。

## 2. 用户操作与接口变化

### 2.1 仅复算当前方案

主界面的“仅复算当前方案”提交 `calculation_full`，payload 为 `{ "mode": "verify", "topN": 0 }`。同步接口 `POST /api/projects/{project_id}/calculation/run` 的 `mode` 同样默认 `verify`。

复算要求有明确保存的计算工况及已确认设计基准。锁定的用户工况优先；否则选择请求的工况，再否则选择最后保存工况。语义设计控制与保存工况不一致、支撑引用失效、没有保存工况时，给出具体错误，要求显式保存输入。复算不会重新生成阶段、加深墙趾、放大梁截面、修改地层、重映射支撑或启动候选优化。

允许保存新的计算结果、任务状态与派生分析证据；给定设计输入保持原值。数据库读取在 verify 路径关闭会修改设计的自动迁移。任务开始前记录项目修订，完成时按该修订提交；用户在计算期间修改项目，旧任务不得覆盖新输入。

### 2.2 优化并采用方案

“优化并采用方案”保留独立显式操作，内部调用使用 `mode="design"`。设计模式允许既有优化器改变方案；仍须遵守工程阻断与结果合同。诊断复算中的 `auto_repair`、`forceClosure`、候选数量等参数不能绕开 verify 的只读输入边界。

本轮没有新增不受约束的智能体自动采用方案功能。算法建议的采用与计算验证保持明确的操作区分。

### 2.3 结果字段

新增 `calculationMode`、`inputBeforeHash`、`inputAfterHash` 和 `derivedDesign`。verify 成功发布时输入前后哈希相同，`derivedDesign.adopted=false`，状态为 `proposal_only`；生成的需求配筋不能替代输入钢筋的承载力验算。

阶段结果增加 `designPressureProfile`、`loadEvidence`、`stageState`、`solveId`、`designGlobalCoupledResult`；墙/围檩包含独立设计作用点、荷载记录 ID 和求解 ID。最终墙包络包含控制阶段、参与求解 ID 和包络哈希。

## 3. 真实状态与不可用结果

界面不再从“有结果对象”“任务结束”“Fail=0”推断工程通过。没有读取到当前性证据、结果过期、缺少数量值、标准/设计任一必需求解失败，都保持未确认或失败。

数值健康的总状态同时检查标准/设计两套全局与墙体求解。原有条件数、残差等数值保持标准作用摘要，使用 `summaryBasis="standard"` 明确口径，界面同步显示；设计作用的不可用或求解器警告不能被标准作用通过掩盖。健康块的条件数、残差、计数、百分比和耗时缺失时显示“未计算”，真实零值仍显示为零。

定量上限 40 mm、计算值 100 mm 时，安全比为 0.4、利用率为 2.5，即使原始标签是 warning，也不能关闭结构问题。None、NaN、Inf 不产生虚构安全系数，不进入自动加固尺寸计算；确属不适用的记录单独标识，不用 999 代表通过。

墙体 FD 失败保留不可用位移。若仅设计作用下 FD 失败，简化跨中估算仍可作为内部诊断，但正式设计 M/V 为 null、设计作用点为空；数值质量与墙体求解证据失败，配筋入口不使用该估算。最终包络缺任一必要贡献时，完整控制值保持未知，历史墙设计结果清除，不调用配筋 sizing。

围檩和冠梁没有当期结果或设计作用证据时，旧设计结果、旧设计弯矩/剪力不能继续显示通过。主界面建议层标明“复算需求与配筋建议（未采用）”。DOCX 汇总结论保留人工复核及未采用建议标识；主成果按钮使用“审查计算书”“审查图纸”“审查成果包”“协调模型”。

## 4. 统一阶段荷载的具体口径

`calculation/stage_loads.py` 提供冻结的 `StageLoadRecord`。内部采用不可变 JSON 快照，读取 PressureProfile 时返回新对象，消费者无法改变已分配荷载 ID 的记录。

当前支持有效应力口径的主动土压力或静止土压力与静水压力分算。不同土水合算方法缺少完整定义时，明确拒绝，避免表面接受设置而暗用另一公式。

当前受限设计作用表达为：

`max(0, importance_factor × (gamma_g × A_G + gamma_q × psi × K × q − R))`

其中 A_G 为坑外零地面超载的土、水作用，R 为坑内被动土与水抗力。坑内有利抗力不随 gamma_g 一起放大；重要性系数在当前实现中作用于完整净作用。`Kq` 是经过主动区受拉截断等处理时的上界增量，标准压力仍直接使用完整超载求得，两者不声明为处处精确可加分解。

墙、全局墙撑、连续围檩和反力迭代共享同一记录；变形使用标准作用，设计需求来自设计作用独立求解，不再对已分项内力统一乘 1.25。单位明确为 kPa、m、kN/m³、角度及无量纲系数。

这是显式、可审计的受限组合实现，尚不是规范全部工况组合的认证。源地层参数仍须确认有效应力含义和资料来源。逆向净荷载、完整承压水与渗流耦合等能力不由本记录推导为已支持。

## 5. 力学修复与阶段边界

### 5.1 已修复的确定性缺陷

- 支撑等效刚度真正进入墙体矩阵，并使用同一刚度恢复反力；全局输出的最终法向刚度只分配一次，不再重复乘投影、支撑或转接折减系数。
- 空间分支消费土刚度因子；墙面荷载、EI、土弹簧采用一致整墙宽度。无支撑均质模型的 1 m 与 10 m 墙面响应保持一致。
- 真实求解向量保持完整精度；不再在求解后用经验规则改写立柱 DOF。可用算例中，序列化向量恢复的方程残差达到测试要求。
- 嵌固筛查的被动覆土从当前坑底开始，消除已挖土层的虚假贡献；整体稳定保留搜索原始最小值，删除向上“校准”覆盖。
- 支撑温度、预加轴力、间隙和立柱竖向力不再用随意百分比附加成已求解结果；未建模项明确待复核，立柱基础设计结果清空。
- 墙体长期刚度折减与全局求解一致；折减乘积不被第二次夹限成另一数值。

### 5.2 显式阶段

自动基准工况包含初始零开挖、支撑安装前开挖状态、同深度安装后状态，以及保留当前临时支撑的最终开挖。默认生成不凭空加入拆撑或底板事件。

阶段快照记录已激活、新安装、已拆除、未激活的支撑，以及楼板首次生效阶段和标高。仅名为 final 不会激活楼板。楼板按显式事件在一个墙节点投入一次；后续状态保留该约束。已拆支撑不会作为“换撑刚度”偷偷留下。

输入拆除未安装支撑、同时激活和拆除、重新激活已拆支撑、无拆除事件即退出、开挖尚未暴露即激活，以及重复/失效 ID 等会被检查。缺同深度安装前状态会给出未覆盖控制工况的审查说明。

当前仍为独立线弹性阶段快照，`historyTransfer="not_implemented"`。土体塑性、安装位移、预应力初始状态和卸载重载历史没有因新增事件状态而自动成为已实现能力。

## 6. 最终响应、包络和配筋

执行顺序为：冻结输入 → 生成阶段状态与荷载 → 标准/设计阶段求解 → 反力迭代 → 重建最终响应摘要与检查 → 汇总最终包络 → 给定配筋验算和需求建议 → 冻结结果合同。

反力迭代使用与首次求解相同的 `solve_stage_response`。松弛仅作为迭代变量，发布的反力来自实际求解。收敛判断采用未松弛目标差；位移以 mm 表达绝对差，以 1 mm 作为近零相对比较的尺度下限。1 mm 变到 9 mm 必须报告 8 mm 变化和 8.0 的相对差，不能误报 0.008 后通过 0.01 容差。

迭代后重新生成界面优先读取的墙位移、支反力、矩阵、残差、楼板和围檩摘要；初次求解数值不能配上最终 solveId。转接梁标准/设计包络分开，标准作用变形与设计作用强度各有来源。围檩截面、材料及实际支撑参数进入求解身份。

配筋阶段不偷偷放大截面并保留旧内力。需改变刚度时必须走显式设计修改及重新求解。输入纵筋/箍筋验算标记 `evidenceScope="supplied_reinforcement"`，建议检查标记未采用。不同钢级按最小实际承载力选取控制配置，不能只取最小钢筋面积。钢筋受力面、根数或箍筋肢数不明确时，保持未计算。

## 8. 仍然阻断工程可用性的事项

1. **被动土抗力与弹性土弹簧共同作用未验证。** 当前净压力已扣除被动抗力，结构模型仍有土弹簧，可能重复计入抗力。新增 `PITGUARD-SOIL-RESISTANCE-MODEL` 失败，工程适用性与正式发行保持 false；不得只删除此门禁以获得通过。
2. **施工阶段尚无完整状态历史。** 安装位移、预应力、应力路径、塑性与卸载重载需要方法选择和独立算例标定。
3. **空间/转接模型仍有近似。** 端部约束、围檩等效刚度、短回墙代理、FD 支点贴近网格节点等须明确适用范围。转接示意极值点不代表完整带符号内力图。
4. **稳定验算仍是未验证筛查。** 修复原始指标及覆土错误不等于补全规范方法；高于阈值仍保留人工复核。
5. **立柱竖向荷载路径与基础未实现。** 不再把水平轴力的 3% 当作竖向荷载。
6. **给定钢筋验算仍属截面子集。** 精确受力面、轴弯剪组合、裂缝、锚固和节点构造仍需完整模型与工程校核。
7. **监测反演独立路径尚有未知值转零遗留。** `services/monitoring_calibration.py` 未纳入本轮修复；不得视作已验证监测校准能力。
8. **CAD/配筋导出未完成同源成果改造。** 审查结论和标签已修正，复杂导出中的建议/采用语义及完整工程图纸仍需专项改造；本轮不承诺施工图可用。

## 9. 升级与回归操作

1. 备份原项目数据库、源资料与导出文件，将此源码包部署到单独测试目录。保持原数据副本可回退。
2. 使用 Python 3.11+ 运行核心应用；可选 OpenSees benchmark 环境使用 Python 3.12+。本轮验证 Python 为 3.12。安装 API 与前端依赖后重新构建，不复用旧 dist。
3. 运行 `python scripts/verify-release-consistency.py`，确认当前包及运行时版本一致。执行 `python scripts/verify-calculation-reliability.py` 复现专项回归；脚本不会把已知全量测试缺口隐去。
4. 打开项目，确认设计基准和保存工况，点击“仅复算当前方案”。没有工况或引用过期时按明确提示保存输入，不把自动修复当作复算。
5. 检查输入前后哈希一致、给定截面/墙趾/钢筋/阶段未变、建议未采用；更改水位或截面后，应要求新结果，不继续使用旧包络。
6. 检查未知、超限及模型限制仍正确阻断。新版本软件/算法/规则/内核/结果管线标识均更新，旧结果应判定需要复算；导出 schema 仍为 3.87，新增字段向后兼容读取。

源码包不包含虚拟环境、node_modules、Git 目录、运行数据库或测试产生的导出文件。安装脚本与原有示例资产保留；示例历史输出不能冒充本版新算结果。本轮未执行生产部署或外部仓库推送。

## 10. 下一步最小工程闭环

下一步应选定一个输入可确认的受撑剖面（例如审计中明确的 A3-3 目标），固定土水处理、土抗力模型、支撑轴向刚度、阶段历史和截面口径，建立手算/解析、独立求解器、项目原模型三层对照。容差先约定，不能观察结果后调整。

只有这条子模型路径通过后，才从同一冻结输入与结果快照生成最小计算书、剖面图、内力包络与配筋表，并在目标 CAD/Word 中完成工程检查。随后再扩展模板、静态规范知识及受控工具智能体。当前的结果身份、荷载合同、不可变复算和未知状态可直接作为这条闭环的基础。
