# V3.87.17 冻结剖面阶段分析与同源成果

## 1. 本轮交付结论

基于已交付的 3.87.16，本轮落实了一条可独立复核的二维排桩剖面链：**显式输入 → 冻结方法与参数 → 连续阶段求解 → 手算/独立求解/网格比较 → 封存结果 → 同源最小成果包**。前端、API、内核、独立适配器、成果生成器及针对实际风险的回归均随源码提供。

当前合成验证例的 6 个状态全部完成，手算核对、OpenSees 同离散输入比较和网格减半检查通过。上传 A3-3 资料的同条件比较保持 `incomplete`，正式设计状态保持 `formalDesignReady=false`。后两项状态有具体的工程缺项，不能由程序测试通过替代。

本轮保留原全基坑计算引擎的 `PITGUARD-SOIL-RESISTANCE-MODEL` 限制。新剖面能力具有独立输入和结果身份；其通过证据不迁移成旧引擎、完整三维基坑或任意工程项目的通过证明。

## 2. 固定什么，才能有可比较的结果

冻结的对象不仅是几何。`app/section/models.py` 要求明确以下工程条件，禁止未知字段、非有限值和静默补参数。

| 冻结域 | 必须明确的内容 | 避免的歧义 |
|---|---|---|
| 坐标与截面 | 标高基准、桩顶、D、桩距 s、桩长、E、I 折减、桩端条件 | 相对模型地面误当建筑标高；单桩与每米宽混用 |
| 土体与水 | 分层边界、天然/饱和重度、c、φ、K0、内外侧 m、土弹簧有效宽度、内外水位 | 只固定 m 数值而未固定其定义；水压力重复计入 |
| 施工阶段 | 开挖深度、水位、均布荷载、安装及拆除的支撑 ID、严格顺序 | 每阶段独立从零计算；安装后立即产生假反力 |
| 支撑 | 位置、单桩水平等效刚度、弹性/刚性、是否只受压 | 每米宽刚度误作单桩刚度；水平反力误作斜撑轴力 |
| 数值方法 | 算法版本、最大单元长度、材料站身份、初始/屈服规则 | 同一输入名称却对应不同方程 |
| 设计与配筋 | 显式内力效应系数及来源、材料曲线、纵筋数/直径/角度、钢筋轴线位置、最小纵筋率 | 系数施加两次；矩形公式冒充圆截面；需求面积误当已配面积 |

使用不可变规范 JSON 保存输入。`snapshotHash` 对应完整输入记录；`analysisHash` 对应工程和数值计算身份；`discreteInputHash` 对应两套求解器共同消费的离散物理条件；`resultHash` 对应封存结果。结果同时记录关键实现源码哈希。取回输入返回隔离副本；修改输入会使前端已显示结果失效。

## 3. 本轮固定的土体抗力方法

### 3.1 明确适用范围

使用单桩 Euler–Bernoulli 梁和两侧独立的理想弹塑性 Winkler 弹簧。适用于本轮定义的平地、垂直排桩、分层有效应力、静水压力、均布地面荷载及二维横向弯曲。桩端自由、铰支或固定必须显式选择。

本方法不直接处理坡台、有限宽或条带邻载、土水合算、渗流、连续土体应力场、地表沉降、空间效应、竖向受力、施工扰动以及整体稳定/抗隆起/渗透破坏。采用独立弹簧也不能从位移相近推导出这些能力已经有效。

CEDD《Deep Excavation Design and Construction》2023 年版 §6.6.3.1 讨论了弹性梁与弹塑性独立土弹簧方法及其限制，§8.3.4–8.3.5 说明支撑预力及拆除阶段的重要性。本实现据此明确模型边界，并用自己的可执行试验核对具体本构和状态转移；文献不替代项目参数校准。

来源：[CEDD 原文](https://www.cedd.gov.hk/filemanager/eng/content_1024/ep1_2023.pdf)。

### 3.2 压力、刚度和荷载分别定义

单桩抗弯刚度为 `EI = E η π D⁴ / 64`。压力按桩距归集，土弹簧刚度按独立冻结的有效宽度归集，两种宽度不互相代替。

```text
Ka = tan²(45° − φ/2), Kp = 1/Ka
σ′v = Σ γ′i Δzi + q
p0 = K0 σ′v
pa = max(0, Ka σ′v − 2c√Ka)
pp = Kp σ′v + 2c√Kp
station force = pressure × pile spacing × tributary integration length
station stiffness = m × depth below current soil surface × effective width × tributary integration length
```

其中 m 的输入单位是 kN/m⁴，站点刚度为 kN/m，站点压力力为 kN。内侧应力积分从当前开挖面开始；坑外均布荷载只进入坑外有效应力。水压力差作为外荷载单独作用一次，土体初始压力/主动界限不会再作为第二份外荷载叠加。

规定压力与静水压力的离散保持合力和一阶力矩。与位移相关的土反力使用独立节点集总近似，不宣称精确再现连续土体的力矩分布；网格减半检查用于检验本近似在当前算例的响应稳定性。

### 3.3 真正继承阶段历史

向坑内位移为正、深度向下为正，内侧材料方向 s=+1、外侧 s=−1。每个存续材料站具有稳定 ID：

```text
ptrial = p0 + k(su − xpl,committed)
p = clip(ptrial, pa, pp)
```

只有阶段收敛后才提交塑性位移；Newton 试算失败不改变上一阶段已提交历史。开挖删除内侧已挖去的材料站，存续站按本轮明确规则重算初始应力、m 深度和压力界限，同时继承已提交的塑性坐标。该规则是本模型的工程假设，应在下一步与原软件的具体历史规则逐项核对。

初始状态要求两侧地面、水位相同，无附加荷载和支撑，平衡由方程自然得到。程序不通过将结果数组清零伪造初始平衡。

零预力支撑在安装前位移处建立参考位置，弹性支撑 `R=K(u−u_install)`；刚性换撑采用真实的非零位移约束。安装换撑和拆旧撑分事件处理。拆撑解除实际构件/约束后再平衡，避免另加一份释放荷载导致重复作用。非零预力需要另建顶升、锁定和实测预力规则，当前拒绝该输入。

某阶段失败会使其后阶段标记 `not_calculated`，不能以零数组生成“完整包络”。

## 7. 审查发现及修复依据

1. **互补压力界限的误判。** 不能把达到主动/被动边界的弹簧全部释放后据此判定失稳。使用二维刚体模态的单向可行方向检查，区分稳定互补拐角和真正全塑性机构。独立 Fraction 有理数法验证 1,029 组配置，两个检查实现与精确判定差异为 0。
2. **细网格残差舍入。** 改用中心化局部弦转角计算梁力，再用 float64 Newton 校正和 longdouble 位移/残差累积改善迭代精度；没有增添虚假刚度，没有放宽力门槛。记录当前 Linux 环境 float64/longdouble 的 nmant 分别为 52/63；不同平台扩展精度不同，达不到原准则时仍明确失败。
3. **圆截面积分精度。** 独立方法发现并固定回归，增加积分点后重新封存最终结果，失败历史保留。
4. **超时后的成果取回。** 网页分析等待设为 180 秒，按冻结输入提供“恢复已保存结果”；结果先保存、后发布索引，恢复仍检查身份。不会因浏览器超时自动重复计算或采用编辑前的迟到响应。

相关证据位于 `V3_87_17_evidence/`。本版针对性回归、完整前端已知失败、真实 HTTP 验证及成果视觉核对分别记录；不把已有测试失败隐藏成全系统通过。

## 8. 使用与复现

在 Python 3.12 环境安装依赖；OpenSees 是独立比较所需的可选 benchmark 依赖，主计算不会用自身结果替代缺失的独立后端。

```bash
uv sync --project services/api --python 3.12 --extra dev --extra benchmark
npm ci --prefix apps/web
uv run --project services/api python scripts/verify-frozen-section.py --require-independent
uv run --project services/api python scripts/run-section-validation.py --example --output verification-output/example
uv run --project services/api python scripts/run-section-validation.py --input my-section.json --output verification-output/my-section
```

`--skip-independent`、`--skip-mesh` 只能显式跳过并记录未运行；不会显示通过。复算已冻结记录可将上次 `snapshot.json` 直接传给 `--input`。独立圆截面审查脚本另依赖 SciPy，复现命令见其文件头及 `independent_circular_section_review_current.md`。

网页进入项目计算页，展开“剖面结果验证”，选择加载验证例或导入输入，审核参数、冻结、计算和下载。页面展示阶段值、支撑水平反力、比较状态和配筋需求，源码哈希等追溯信息折叠。当前入口验证独立剖面，不擅自提取不完整工程数据填成“已确认输入”。

## 9. 原项目的下一步条件与顺序

已从上传报告建立 320 项证据字段，区分 197 项原文事实、44 项明确解释与 79 项缺失；见 `examples/frozen-section/A3-3-reference-audit.json/.md`。A3-3 报告包含坡台、有限宽邻载及土水合算/分算混用，且未完全定义 E/EI、m 法、桩端与内力宽度身份，不能用本轮平地有效应力模型作百分误差验收。

下一轮应依次完成：

1. **冻结原生基准。** 保留 FRWS 原生项目、软件版本及全部计算选项，核对标高、E/I、m 的单位和深度基准、有效宽度、桩端、冠梁/支撑生效时刻，以及 M/V 是单桩还是每米。报告抄录与工程解释继续分字段保存。
2. **形成单一方法差异表。** 针对坡台、有限宽邻载、土水合算、卸载及材料重置规则，明确原模型公式和程序实现。不得通过调 m 让峰值凑近来替代方法一致。
3. **按阶段而非只看最终最大值比较。** 同时核对两侧压力、位移曲线、M/V 曲线、支撑水平反力、安装参考位移、控制阶段及设计系数；缺单位身份的指标不出相对误差。
4. **补工程验算后扩成果。** 先补抗剪、裂缝、轴弯、锚固及构造，再将验证后的剖面输入/结果接入实际工程剖面与图签体系。先保有一张可核对剖面和完整来源，再扩展平面、节点、详图和总图。
5. **智能体只编排可校核步骤。** 可负责从资料提取候选参数、列差项、创建待确认快照、调用求解器、解释差异和生成同源成果。公式、本构、参数确认、阶段修改及工程结论必须走显式合同和结果验证，不让自然语言直接改设计输入或凭描述补出内力。

静态资产现在应优先固定为四类版本化文件：输入 JSON Schema/单位字典、可执行解析与原项目基准、带出处的参数/方法证据表、基于统一结果结构的计算书和图纸模板。它们已有初步载体；无需先建设宽泛的知识库来替代当前最缺的可复算工程证据。
