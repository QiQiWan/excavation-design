## Comparison behavior

- Conditions require snapshot/reference/contract hashes to agree, non-synthetic source provenance, original field readiness, explicit critical input bindings, stage identity, force basis, signs and characteristic-effect identity.
- Unknown methods and missing input bindings stay blockers; no peak fitting or implicit sign/datum/spacing changes.
- Strict JSON rejects unknown fields, units, nonfinite values, inconsistent duplicate samples and out-of-domain samples. Declared per-metre M/V/reactions convert using explicit positive pile spacing only.
- One-sided samples are retained. Hermite service samples tagged `within`/`interior` export as `continuous`, retaining both depth and value.
- Comparison interpolates only inside explicitly compatible segments, never across unsampled boundaries or beyond coverage. Reports max error/depth/side, bias, RMSE, signed extrema, missing samples/boundaries, coverage fraction and missing length in metres.
- `coverage.displacementMomentShearComplete` and `coverage.pressureProjectionComplete` independently identify coverage. Full original acceptance cannot arise from matching UMV while pressure/original conditions are missing.
- Pressure recovery uses summed Gauss/nodal-lumping spring forces divided by spacing and total integration weight, plus weighted **externalWaterKpa**. V2 total-combined soil does not get physical pore pressure added twice. No artificial pressure boundary samples are generated.
- Removed support keeps installation reference displacement and known zero reaction; not-installed values remain unavailable. Actual member axial force is a separate optional metric, not a relabeled wall reaction and not a mandatory horizontal-section acceptance gate.
- Envelope comparison retains all rounding-tied controlling stages. Reinforcement export retains all computationally tied bending-control stages and compares required/provided areas separately from design effects.
- `sameConditionsVerified`, numerical status and `formalDesignReady` remain distinct; formal design readiness is always false in this comparison module.
